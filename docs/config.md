# Configuration Reference

Generated by `tests/config-reference.py --write` from `plugins/seyag/config/knobs.tsv`; do not edit by hand.

## Scope

Every environment variable with prefix `SYG_*`, `CLAUDE_USAGE_*`, `ZAI_*`, `PLUGIN_RELEASE_*`, `PRICE_TABLE_*`, `SECURITY_SWEEP_*`, `RAILWAY_OPS_*`, `CONTEXT_AUDIT_*`, `LINES_CHECK_*`, `OPENROUTER_*`, `CC_ROUTE_*`, `PR_CI_WAIT_*`, `TZUROT_ALLOW_*`, plus `CLAUDE_PROJECTS_DIR`, `CLAUDE_SESSION_ARCHIVE`, `SESSION_LEDGER`, `SEYAG_KEYS_BIN`, `CLAUDE_VERSIONS_DIR`, `CLAUDE_PLUGIN_REGISTRY`, `ANTHROPIC_ADMIN_API_KEY`, `CLAUDE_CONFIG_DIR`, found in files under `plugins/` other than `*.md` and `*.probe.sh`. Not listed: variables that the Claude Code harness, `gh`, the shell or XDG define and seyag only reads (for example `CLAUDE_PROJECT_DIR`, `CLAUDE_PLUGIN_ROOT`, `CLAUDE_JOB_DIR`, `CLAUDE_CODE_*`, `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_API_KEY`, `GH_*`, `XDG_*`, `HOME`); the listed names from those systems are ones seyag honours as overrides. `Found in` lists every such file that mentions the name, comments included, except `hooks/lib/config-env.sh` for the harness-owned names, which it mentions only to refuse them.

## How to set a value

Set user variables in the `env` block of a Claude Code `settings.json` (`~/.claude/settings.json` for user scope, `.claude/settings.json` for project scope, or `.claude/settings.local.json` for local scope; the more specific scope wins):

```json
{
  "env": {
    "SYG_PROFILE": "full"
  }
}
```

Exception: the per-command `SYG_ALLOW_*` bypasses of the shell guards are written into the command itself (for example `SYG_ALLOW_RM=1 rm -r build`), not into settings; each row says so. `SYG_ALLOW_LIVE_CHECKOUT` is the one also read from the environment.

## Config files (config.toml)

An optional TOML file fills in knobs the environment left unset: user `${XDG_CONFIG_HOME:-$HOME/.config}/seyag/config.toml`, then project `${CLAUDE_PROJECT_DIR:-$PWD}/.claude/seyag.toml` (project keys overwrite user keys). The environment wins over both, even when set to the empty string. Keys map mechanically to env names, the key path uppercased with the separators turned into underscores: `claude_usage_week_reserve = 61` and `[claude_usage]` + `week_reserve = 61` both set `CLAUDE_USAGE_WEEK_RESERVE`. A key applies iff its env name is a user-scope row of this registry and not harness-owned; command-execution knobs — names ending `_CMD` and the binary-path knobs the loader lists beside them — cannot be set from the project file. Subset per line: blank, full-line comment, `[section]` header, or `key = value` with a quoted string (basic `"`, escapes `\\` `\"` `\t` `\n` only, or literal `'`), an integer, a float, or `true`/`false` (exported as `1`/`0`); strings and paths must be quoted, and arrays, inline tables, multiline strings and trailing content are unsupported; a comment may follow a value but not a section header. `SYG_CONFIG=0` disables the loader. A bad file warns on stderr and is skipped, never blocks a hook — and warns again on every hook call. The project file has the same trust level as the project's `settings.json` `env` block: a cloned repo can set any knob it names, guard bypasses included, so trust a repo before letting its `.claude/seyag.toml` load.
